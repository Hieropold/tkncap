# tkncap

CLI viewer of current tokens capacity for Claude Code and Gemini

## Build

You can build the project using the standard Go toolchain. First, ensure all dependencies are downloaded:

```bash
go mod tidy
```

Then build the project:

```bash
go build -o tkncap .
```

To install it directly to your `$GOPATH/bin`:

```bash
go install .
```

## Configuration

`tkncap` discovers accounts via environment variables at runtime. No configuration file is required.

The environment variable naming convention is:
`TKNCAP_<PROVIDER>_<ACCOUNT>_<FIELD>=<value>`

### Setting up multiple Claude accounts

The process of managing multiple Claude accounts involves two parts:

1. Configuring the Claude CLI itself to use different accounts.
2. Configuring `tkncap` to monitor these separate accounts.

#### 1. Configuring Claude CLI

The Claude CLI stores credentials and configuration in a single directory (by default `~/.claude`). To use multiple accounts, you need a small workaround to maintain separate config directories (e.g., `~/.claude-work`, `~/.claude-personal`).

**Manual `CLAUDE_CONFIG_DIR` setup:**
Log in once per account, saving each session into its own folder by specifying the `CLAUDE_CONFIG_DIR` environment variable:

```bash
CLAUDE_CONFIG_DIR=~/.claude-work claude login
CLAUDE_CONFIG_DIR=~/.claude-personal claude login
```

Then bind shortcuts in your shell config (`.zshrc` or `.bashrc`):

```bash
alias claude-work='CLAUDE_CONFIG_DIR=~/.claude-work claude'
alias claude-personal='CLAUDE_CONFIG_DIR=~/.claude-personal claude'
```

This lets you run `claude-work` vs `claude-personal` and they stay isolated, meaning authentic sessions for both accounts are saved at the same time, without repeated logins.

_(Alternatively, you can use thin wrappers like `claude-switch` or `cloak` that manage multiple profiles behind the scenes.)_

#### 2. Configuring tkncap

To check usage and quotas for these multiple Claude accounts simultaneously in `tkncap`, configure an environment variable for each account. Ensure that the `<ACCOUNT>` label is unique (e.g., `WORK`, `PERSONAL`).

For Claude, the required `<FIELD>` is `CREDENTIALS_PATH`, which should point to the session credentials file (`.credentials.json`) generated by Claude Code in the respective configuration directory.

Example configuration for multiple accounts:

```bash
export TKNCAP_CLAUDE_WORK_CREDENTIALS_PATH=~/.claude-work/.credentials.json
export TKNCAP_CLAUDE_PERSONAL_CREDENTIALS_PATH=~/.claude-personal/.credentials.json
```

Once exported, running `tkncap show` will automatically discover and display the token capacity for both configured accounts.

### Setting up Gemini accounts

For Gemini, the required `<FIELD>` is `API_KEY`. You can obtain an API key from the [Google AI Studio](https://aistudio.google.com/).

Example configuration for a Gemini account:

```bash
export TKNCAP_GEMINI_MAIN_API_KEY=AIza...
```

Once exported, running `tkncap show` will automatically discover and display the Requests Per Minute (RPM), Tokens Per Minute (TPM), and Requests Per Day (RPD) quotas for your Gemini account.
